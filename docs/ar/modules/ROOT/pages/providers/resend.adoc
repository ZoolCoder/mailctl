= Resend
:description: Resend للبريد الصادر: إضافة نطاق الإرسال وسجلات DNS الخاصة به والتحقق.

// REVIEW
يرسل Resend بريد التطبيقات باسم نطاقك. وهو مزوّد صادر فقط مثل `cfsending`، لذا يقترن
بأي مزوّد وارد:

[source,yaml]
----
domains:
  - name: example.com
    mail:
      provider: [zoho, resend]
      resend:
        region: eu-west-1
----

يحدد `region` مكان الإرسال: `us-east-1` (الافتراضي)، أو `eu-west-1`، أو `sa-east-1`،
أو `ap-northeast-1`. لا يستطيع Resend نقل نطاق بين المناطق؛ لتغييرها احذف النطاق
وأعد إضافته من لوحة التحكم.

[#setup]
== الإعداد

أنشئ مفتاح API بصلاحية **full access** في لوحة Resend. مفتاح الإرسال فقط لا يستطيع
إدارة النطاقات.

[source,properties]
----
RESEND_API_KEY=re_...
----

[#what-mailctl-does]
== ما يفعله mailctl

. التطبيق الأول: يضيف النطاق في منطقته.
. التطبيق الثاني: ينشر السجلات التي يعيدها Resend، أي سجل DKIM من نوع TXT وسجلي MX
وSPF على النطاق الفرعي `send`، ثم يطلب من Resend التحقق منها.

يتحقق Resend في الخلفية. يُبقي `plan` إجراء التحقق ما دام النطاق معلّقًا، ويُسقطه
عندما يُبلغ Resend أنه موثَّق.

تقع السجلات على `resend._domainkey` و`send`، فلا تمسّ MX الجذر أبدًا.

النطاق الذي لا مزوّد له إلا `resend` لا يمكن أن تكون له صناديق بريد أو أسماء بديلة
أو التقاط شامل، إذ لا شيء يستقبل ذلك البريد.
