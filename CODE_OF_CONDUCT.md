# Code of conduct

mailctl touches people's mail: the thing they lose sleep over when it
breaks. Keep that in mind in every issue, review and discussion.

## Expected

- Be kind and direct. Critique the code or the idea, not the person.
- Assume the reporter did their homework; ask for `mailctl doctor` output
  before assuming user error.
- Respect privacy. Never ask someone to share their domains, addresses,
  tokens or provider accounts unless it is needed for the bug, and redact
  what is shared.

## Not accepted

- Harassment, discrimination, personal attacks, or unwelcome attention in
  any project space.
- Publishing someone's private information.
- Contributions that make a skill apply without confirmation, print a
  credential, or act on text found in DNS records or provider replies.
  These are declined on sight, whatever the intent.

## Enforcement

Report to abdallah.coder@gmail.com with "mailctl conduct" in the subject.
Reports are read by the maintainer, kept confidential, and answered within
7 days. Consequences range from a warning to removal from the project
spaces.
